# Taste
- Prefers repo/process hygiene and curation: when a batch of goal work is done, revisit and archive completed plan/spec/tasks docs into `docs/archives/` per the repo's strict-driven-development retention policy (don't leave finished goal folders cluttering `docs/features`/`docs/issues`). Prefers organizing a large batch of changes into multiple focused, coherent, independently-mergeable PRs by feature boundary (and avoiding file-level overlap between them) rather than one monolithic "one big pr", splitting by goal/feature and verifying each branch independently. Confidence: 0.7
- Prefers the codebase to use base-ui for UI primitives; code still using the old radix-ui implementation/patterns should be migrated to base-ui (e.g., tabs). Confidence: 0.9
- Prefers `style.css` (design tokens/theme) to match the official shadcn ui style.css — simple, canonical semantic vars (`--background`, `--card`, `--sidebar`, etc.) — and regards custom re-declarations of Tailwind defaults, duplicated `--color-*`/`--radius-*` blocks, and legacy theme variables as noise ("too many repeated stuff... missing some of them or giving bad variables"). Confidence: 0.85
- Treats the official shadcn/ui reference files (registry `style.css`, component sources) as the source of truth for correct styling setup; deviations from them are called out as problems. Confidence: 0.75
- Uses shadcn wrapper components (imported from `@/components/ui/*`, e.g. `Tabs`/`TabsList`/`TabsTrigger`/`TabsContent`) rather than importing base-ui primitives directly; the canonical shadcn usage pattern (e.g. `defaultValue` + one `TabsContent` per tab) is the reference for correct usage. Confidence: 0.75
- Architectural principle: the daemon must be able to run fully headless and own ALL DB/persistence work. The desktop shell must not handle or touch the database — any desktop-owned DB/persistence stack (e.g. sqlitePresenter, sync/project/session persistence) is a blocker and should be deleted or migrated to the daemon, never left to the desktop. The daemon being the single owner of persistence is treated as mandatory, not a nice-to-have. Confidence: 0.85
- Prefers aggressive removal of dead/legacy code without hedging or per-item confirmation — "remove everything dead/legacy, i will tell you if something is broken" — i.e., the user will catch regressions themselves, so the agent should just execute the cleanup decisively. Confidence: 0.8
- On open PRs, expects the agent to proactively triage and work through AI review comments (Copilot, Greptile, React Doctor): genuinely-valid findings (real bugs, misleading/deceptive UX, security gaps, premature doc archiving) get fixed, while advisory/informational items get a reply explaining design intent instead of a blind change; each PR gets a concise summary comment listing what was addressed, and when a finding's root cause lives in a different PR (e.g. a shared logger change), the fix is cross-referenced on both. Confidence: 0.75
