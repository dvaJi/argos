# Workspace-as-Server Architecture

## Problem

Currently, the app has a binary local/remote toggle in Settings. When connected to a remote daemon, its sessions mix with local ones in the sidebar. Switching back to local requires going to Settings and flipping the toggle. Only one remote daemon can be connected at a time. The "workspace" concept (file/project directory) is conflated with the server concept.

## Solution

Reframe workspaces as server connections. Each workspace = one daemon (local or remote). The sidebar gets a workspace selector at the top. Switching workspaces filters sessions and preserves per-workspace state.

## Implementation Plan

### Step 1: Workspace Config Model (`shared/workspaceConfig.ts`)

Extend the existing `serverConfig.ts` pattern to support multiple workspaces:

```ts
type WorkspaceEntry = {
  id: string;           // "local" | generated UUID for remote
  name: string;         // User-friendly name
  mode: "local" | "remote";
  remoteUrl: string;    // Empty for local
  authToken: string;    // Empty for local
  isActive: boolean;
  createdAt: number;
};

type WorkspaceConfig = {
  workspaces: WorkspaceEntry[];
  activeWorkspaceId: string;
};
```

- Default: `[{ id: "local", name: "Local", mode: "local", ... }]`
- `readWorkspaceConfig()`, `writeWorkspaceConfig()`, `subscribeWorkspaceConfig()`
- Migrate existing `argos-server-config` → workspace format on first read
- Use `argos-workspace-config` localStorage key

### Step 2: Workspace Store (`renderer/stores/ui/workspace.ts`)

TanStack Store managing workspace state:

```ts
const workspaceStore = new Store({
  workspaces: [] as WorkspaceEntry[],
  activeWorkspaceId: "local",
  activeSessionPerWorkspace: {} as Record<string, string | null>,
  connectionStates: {} as Record<string, ConnectionState>,
});
```

Actions:
- `switchWorkspace(id)` — Sets active, loads sessions for that workspace, restores active session
- `addWorkspace(entry)` — Add remote workspace, connect to it
- `removeWorkspace(id)` — Disconnect and remove
- `renameWorkspace(id, name)` — Update display name
- `getActiveSessions()` — Returns sessions filtered to active workspace

### Step 3: Multi-Workspace Connection (Preload)

Modify `preload/index.ts` to manage multiple concurrent connections:

```ts
const workspaceConnections = new Map<string, {
  adapter: WebSocketBridgeAdapter | null;  // null = local IPC
}>();
```

- On workspace config change: connect/disconnect adapters as needed
- Expose `setActiveWorkspace(id)` IPC to renderer → preload
- `HybridBridge` gets `setActiveWorkspace(id)` which swaps its `wsBridge` reference

### Step 4: Connection State Updates

Extend `ConnectionState` in `shared/contracts/connection.ts`:

```ts
const ConnectionStateSchema = z.object({
  mode: z.enum(["local", "remote"]),
  url: z.string().nullable(),
  connected: z.boolean(),
  lastError: z.string().nullable(),
  workspaceId: z.string().optional(),  // NEW
});
```

### Step 5: WorkspaceSelector Component

UI component at the top of the sidebar session column:

```
┌─────────────────────────────────┐
│ 🏠 Local              ▼  │  ← dropdown trigger
│    ┌─────────────────────────┐  │
│    │ ● Local          [active]│  │

│    │ ○ My GPU Box             │  │
│    │ ───────────────          │  │
│    │ + Add Workspace          │  │
│    │ ⚙ Settings               │  │
│    └─────────────────────────┘  │
├─────────────────────────────────┤
│ Session list (filtered)         │
```

- Dropdown shows all workspaces with connection status dots
- Active workspace is highlighted
- "Add Workspace" opens a dialog for remote URL + token
- Click a workspace → `switchWorkspace(id)`

### Step 6: Session Filtering

Modify `sessionStore` to be workspace-aware:

- Each workspace has its own session list
- `fetchSessions()` fetches from the active workspace's bridge
- `activeSessionPerWorkspace` tracks which session is active per workspace
- On workspace switch: save current active session, restore target's active session

### Step 7: Settings Migration

Update `ServerSettings.tsx` to work with workspace model:
- Instead of a local/remote toggle, show the workspace list
- "Add Remote" button opens the same dialog as the sidebar selector
- Removing a workspace disconnects it
- The old `argos-server-config` localStorage is migrated on first load

## Data Flow

1. User clicks workspace in sidebar selector
2. `workspaceStore.switchWorkspace(id)` called
3. Preload notified via IPC: `setActiveWorkspace(id)`
4. Preload swaps `hybridBridge.setWsBridge(newAdapter)`
5. Session store re-fetches sessions from the new bridge
6. Active session restored from `activeSessionPerWorkspace[id]`

## Edge Cases

- **Local daemon not running**: Show "offline" status, sessions from last known state
- **Remote connection fails**: Show error state, retry with backoff (existing reconnect logic)
- **Workspace removed while active**: Switch to "local" workspace
- **First launch (migration)**: Read old `argos-server-config`, create workspace entries

## Verification

1. Start app → see "Local" workspace in sidebar selector
2. Add remote workspace via "Add Workspace" → appears in list, connects
3. Switch to remote → sidebar shows remote sessions only
4. Switch back to local → local sessions restored
5. Each workspace remembers its active chat session
6. Restart app → workspaces restored from localStorage
7. Settings page shows workspace list, can add/remove from there too
