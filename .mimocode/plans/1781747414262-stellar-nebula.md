# Plan: Merge Settings Window into Main Renderer as Route Layouts

## Goal

Replace the separate Settings Electron window with in-app routes using TanStack Router layouts. Settings becomes a completely different layout within the same window — when navigating to `/settings/*`, the entire UI switches from the chat layout (AppBar + WindowSideBar) to a settings layout (settings chrome + settings nav sidebar). Back/close navigates to `/chat` via the router.

Splash, Floating, and BrowserOverlay remain as separate Electron windows.

---

## Architecture

### Current Route Tree
```
__root.tsx → App.tsx (AppBar + WindowSideBar + Outlet)
  / → redirect → /chat
  /chat → ChatTabView
  /welcome → WelcomePage
```

### Target Route Tree
```
__root.tsx → RootShell (shared providers, theme sync, Toaster, global dialogs)
  _main.tsx → MainLayout (AppBar + WindowSideBar + Outlet) [pathless layout]
    /chat → ChatTabView
    /welcome → WelcomePage
    index → redirect → /chat
  settings.tsx → SettingsLayout (settings chrome + settings nav + Outlet) [layout route]
    settings/overview → SettingsOverview
    settings/common → CommonSettings
    settings/display → DisplaySettings
    settings/provider → ModelProviderSettings (with $providerId child)
    ... (all 19 settings pages)
    settings/index → redirect → /settings/overview
```

---

## Step-by-Step Implementation

### Step 1: Create the Root Shell (`__root.tsx`)

Extract shared initialization from `App.tsx` into a minimal root layout:
- Theme syncing (themeStore, uiSettingsStore → CSS classes)
- Font manager
- Global providers that both layouts need
- `<Outlet />` for layout switching

**File:** `apps/desktop/src/renderer/src/routes/__root.tsx`

The root shell should NOT render AppBar or WindowSideBar — those belong to `_main.tsx`.

### Step 2: Create the Main Layout (`_main.tsx`)

Move the main-app-specific shell from `App.tsx` into a pathless layout route:
- `AppBar` component
- `WindowSideBar` component
- Main-specific initialization (session management, onboarding, deeplinks, spotlight, etc.)
- `<Outlet />` for `/chat` and `/welcome`

**New file:** `apps/desktop/src/renderer/src/routes/_main.tsx`
**Move:** Main-specific init logic from `App.tsx` → `_main.tsx`

### Step 3: Create the Settings Layout (`settings.tsx`)

Convert the settings window chrome into a layout route:
- Settings window title bar (with close/back button that does `router.navigate({ to: '/chat' })`)
- Settings navigation sidebar (groups + items from `getSettingsNavigationGroups`)
- `<Outlet />` for settings child pages
- Settings-specific initialization (provider store, model store, settings IPC events)

**New file:** `apps/desktop/src/renderer/src/routes/settings.tsx`

Port the layout UI from `src/renderer/settings/App.tsx` (lines 612-664) — the title bar and settings nav sidebar.

### Step 4: Create Settings Page Routes

Create file-based routes for all 19 settings pages. Each route file imports the corresponding component from `src/renderer/settings/components/`.

**New files in `apps/desktop/src/renderer/src/routes/settings/`:**
```
settings/
  index.tsx              → redirect to /settings/overview
  overview.tsx           → SettingsOverview
  common.tsx             → CommonSettings
  display.tsx            → DisplaySettings
  environments.tsx       → EnvironmentsSettings
  provider.tsx           → ModelProviderSettings (layout for /settings/provider)
  provider/
    $providerId.tsx      → ModelProviderSettings (detail)
  argos-agents.tsx       → ArgosAgentsSettings
  acp.tsx                → AcpSettings
  mcp.tsx                → McpSettings
  server.tsx             → ServerSettings
  remote.tsx             → RemoteSettings
  notifications-hooks.tsx → NotificationsHooksSettings
  scheduled-tasks.tsx    → ScheduledTasksSettings
  plugins.tsx            → PluginsSettings
  skills.tsx             → SkillsSettings
  prompt.tsx             → PromptSetting
  knowledge-base.tsx     → KnowledgeBaseSettings
  database.tsx           → DataSettings
  shortcut.tsx           → ShortcutSettings
  about.tsx              → AboutUsSettings
```

### Step 5: Move Settings Components

Move settings page components from `src/renderer/settings/components/` into the main renderer's component tree, since they'll now be imported by the main renderer routes.

**Source:** `apps/desktop/src/renderer/settings/components/*.tsx`
**Destination:** `apps/desktop/src/renderer/src/components/settings/*.tsx`

Update imports in each moved file (e.g., `@/stores/` stays the same, relative imports change).

### Step 6: Update Settings Opening Logic

Change how settings is opened — from creating a new BrowserWindow to navigating the current window's router.

**Files to modify:**
- `apps/desktop/src/renderer/api/SettingsClient.ts`: `openSettings()` now sends a custom event or IPC that triggers router navigation instead of `createSettingsWindow`
- `apps/desktop/src/renderer/src/components/WindowSideBar.tsx`: `openSettings` callback uses `router.navigate({ to: '/settings/overview' })` directly
- `apps/desktop/src/main/routes/index.ts` (line 2589-2601): `systemOpenSettingsRoute` handler — instead of `createSettingsWindow`, send IPC to the renderer to navigate to settings
- `apps/desktop/src/main/presenter/windowPresenter/index.ts`: `SHORTCUT_EVENTS.GO_SETTINGS` handler — navigate existing main window instead of creating settings window

### Step 7: Update Main Process

Modify `WindowPresenter` to support navigating the main window to settings:

**File:** `apps/desktop/src/main/presenter/windowPresenter/index.ts`
- `createSettingsWindow()` →改为 `navigateToSettings(navigation)` — sends IPC to main window to navigate to `/settings/overview` (or specific settings route)
- Remove `settingsWindow` singleton and related state (`settingsWindowReady`, `pendingSettingsMessages`, `pendingSettingsProviderInstalls`)
- Update `sendToAllWindows()` to stop sending to settings window separately
- Update `SHORTCUT_EVENTS.GO_SETTINGS` handler

### Step 8: Clean Up Settings Renderer

Remove the now-unused settings renderer entry point:

**Files to delete/modify:**
- `apps/desktop/src/renderer/settings/index.html` — remove
- `apps/desktop/src/renderer/settings/main.tsx` — remove (router setup moves to main renderer)
- `apps/desktop/src/renderer/settings/App.tsx` — remove (layout moves to `settings.tsx` route)
- `apps/desktop/vite.config.ts` — remove `settings` from `rolldownOptions.input`
- `apps/desktop/src/preload/index.ts` — check if settings-specific preload is needed (probably not, uses same preload as main)

### Step 9: Handle Settings IPC Events in Main Renderer

The settings renderer currently listens for IPC events (`SETTINGS_EVENTS.NAVIGATE`, `SETTINGS_EVENTS.PROVIDER_INSTALL`). These need to work in the main renderer context.

**File:** `apps/desktop/src/renderer/src/routes/settings.tsx`
- Listen for `SETTINGS_EVENTS.NAVIGATE` → call `router.navigate()` to the target settings page
- Listen for `SETTINGS_EVENTS.PROVIDER_INSTALL` → trigger provider install flow
- Handle `SETTINGS_EVENTS.READY` → no longer needed (no separate window)

### Step 10: Update Vite Config

**File:** `apps/desktop/vite.config.ts`
- Remove `settings: resolve('src/renderer/settings/index.html')` from `rolldownOptions.input`
- Keep all other entries (index, browserOverlay, floating, splash)
